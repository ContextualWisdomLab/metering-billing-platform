# ADR 0001: Own Commercial Truth Internally

**Status:** Accepted

## Context

Payment processors, merchant-of-record services, and billing engines expose different customer, meter, invoice, and settlement models. If CWL treated a provider object identifier as the internal primary key, a provider outage or migration would rewrite commercial identity. Usage producers, rating, entitlements, and invoice intent would then depend on a replaceable adapter.

Three claimed standards constrain how commercial facts enter and leave this control plane:

- Usage arrives as events. The CloudEvents specification defines a vendor-neutral envelope so source and event identity can be preserved for at-least-once delivery with at-most-once monetary effect (Cloud Native Computing Foundation, 2022). The technical requirements already require CloudEvents-compatible envelopes in the event milestone.
- Cost, invoice, billing-period, and commitment datasets used for FinOps export are not the same thing as the operational billing schema. FOCUS 1.4 is an open billing-data specification for uniform export, including invoice-reconciliation and billing-period datasets (FinOps Foundation, 2026). This repository must not treat a FOCUS row as the internal meter, rating, or invoice-intent record.
- Bank and treasury messages have their own metamodel. ISO 20022-1:2026 defines the universal financial-industry message scheme used by versioned payment-message mappings (International Organization for Standardization, 2026). Proprietary provider fields must not become columns in the accounting or settlement core.

The product therefore needs a provider-neutral commercial authority that can continue when a provider is unavailable, while still projecting usage, invoices, and settlement evidence to replaceable adapters.

## Decision

CWL owns canonical usage, meter, price, contract, rating, entitlement, invoice-intent, and reconciliation records. External services are capability adapters and projections.

- Internal identifiers are generated by this platform. Provider customer, subscription, invoice, and settlement identifiers live only in mapping records.
- Future usage-event envelopes preserve CloudEvents source and event identity so duplicate delivery returns the existing receipt rather than a second monetary effect.
- FOCUS 1.4 cost, invoice, billing-period, and commitment data are export projections. They are not the internal operational schema.
- Bank and treasury adapters apply versioned ISO 20022 mappings. The commercial core stores settlement evidence and expected-versus-actual reconciliation, not proprietary payment-message fields.

Provider checkout, collection, refund, dispute, tax-document, and settlement capabilities remain separate ports. A provider implements only the capabilities it declares.

## Consequences

- Provider migration changes adapters and mappings rather than core identifiers.
- Internal billing can continue when a provider is unavailable.
- CWL must maintain deterministic rating and reconciliation evidence.
- Usage ingestion must be idempotent on envelope identity before a payment-provider adapter is added.
- FinOps and payment-message consumers can change export mappings without rewriting meters, contracts, or invoice intent.
- This decision does not make the platform a FOCUS dataset generator or an ISO 20022 message store. Those remain projection and adapter concerns.
